# 双模式编码工作流：验收规格（Fork）

状态：v1.0 / 实施中的验收契约。此文件描述**目标**，不代表下列项目已经通过测试。实现记录与差距见 [coding-workflow-dual-mode.zh.md](coding-workflow-dual-mode.zh.md)。

## 冻结决策

| 项目 | 值 |
|---|---|
| 默认模式 | \`manual\`；现有 Skill Launcher 保持兼容 |
| 全自动人工确认 | \`exceptions\`；只有重大歧义、风险、权限或越界需要人工介入 |
| 自动提交 | \`local\`；仅本地 Git commit，不执行 push、PR、部署 |
| 自动修复 | 至多 3 轮；连续 2 轮无进展停止 |
| 恢复 | 应用重启恢复检查点，但必须经用户再次授权，不允许自动复活 |
| 代码边界 | Fork 插件，保持 DSH Agent Loop / Session / Permission 核心不变 |

## 统一阶段

| ID | 阶段 | 产物 | 关键门禁 |
|---|---|---|---|
| S0 | 工作区预检 | 分支、HEAD、干净状态、Skill/工具清单 | 不覆盖原有改动，不直接提交主分支 |
| S1 | 需求分析 | 目标、约束、验收条目 | 重大歧义暂停确认 |
| S2 | 需求固化 | 有版本的 spec | 有可测试的接受条件 |
| S3 | 实施计划 | 修改范围、执行步骤、测试与构建命令 | 不超出 S2，确定预期文件及必要校验 |
| S4 | 代码实现 | 当前真实源码 diff、相关测试 | 修改路径可归属到任务 |
| S5 | 代码走读 | 问题编号、等级、文件位置、证据 | P0/P1 不得未解决 |
| S6 | 修复闭环 | 修复证据及复审 | 修复回 S5，禁止无限循环 |
| S7 | 编译验证 | 实际命令、退出码、日志、源码指纹 | 所有必需检查通过且仍匹配当前 diff |
| S8 | 本地提交 | 本地 SHA、文件范围、行数统计 | 安全检查、准确暂存、钩子成功，无远程写入 |
| S9 | 交付报告 | 规格、变更、验证、遗留、SHA | 不能把未运行项目写成通过 |

S6 无问题时可以标记 \`skipped\`（明确原因），但被跳过的必需测试或编译不能算通过。

## 状态与切换

任务状态：\`created\`、\`ready\`、\`running\`、\`waiting_approval\`、\`paused\`、\`blocked\`、\`completed\`、\`cancelled\`。

阶段状态：\`pending\`、\`running\`、\`waiting_approval\`、\`completed\`、\`failed\`、\`blocked\`、\`skipped\`、\`stale\`。

- 状态由 Host 权威存储管理，并与 taskId/session/workspace/branch/base HEAD 关联。切换模式复用同一 Work Item。
- \`manual → auto\` 只继续未完成/已失效阶段；\`auto → manual\` 先安全暂停，停止后续调度。
- S2/S3 实质变化使 S4 及后续相关证据失效；源码修改使 S5/S7 失效；S7 之后代码变化严禁提交。
- 用户审批必须是限定范围的一次性授权，未经审批不得靠模型提示词自行绕过。
- 任何崩溃、中断、重连都必须通过版本/检查点比对恢复，绝不自动重跑已执行的本地 commit。

## 分阶段验收

### P1：双模式基础

- P1-01：新建任务默认 manual，原有按钮自定义、排序、更多、导入导出不回归。
- P1-02：手动流程由用户逐步发起；确认、退回、重跑、跳过有明确状态与理由。
- P1-03：工作项持久保存在 Host；重启展示原状态，但不自行启动新操作。
- P1-04：源产物变化能让依赖阶段变为 stale，停止使用旧验证证据。
- P1-05：工作区/Session 隔离、并发版本冲突和缺失 Skill 必须显式失败。
- P1-06：Windows Desktop 与 Web 对同一任务状态的呈现一致。

### P2：自动编排

- P2-01：明确低风险目标能在授权后自动执行 S0～S7，中间无需无意义的人工确认。
- P2-02：权限/数据/安全/范围重大异常必须进入 waiting_approval 或 blocked。
- P2-03：审查失败进入 S6，修复后 S5 再检查；至多 3 轮，2 轮无进展停止。
- P2-04：缺工具、缺依赖、构建失败、预算耗尽不得宣称完成。
- P2-05：暂停、恢复、切手动和重启后继续不能出现重复阶段或并发写操作。
- P2-06：自动执行的进度、输入、实际产物和阻塞理由可在 UI 查看。

### P3：本地提交与桌面稳定性

- P3-01：真实走读+构建+测试证据有效时自动执行**一次**本地 commit。
- P3-02：未归属改动、混杂暂存、冲突、敏感文件必须阻塞，不允许无差别 add。
- P3-03：从干净 main/master 创建专用任务分支，不直接自动提交主分支。
- P3-04：源文件变化造成审查/构建指纹失效，不得沿用旧结果。
- P3-05：提交钩子失败不可跳过，重复恢复不可重复提交。
- P3-06：交付报告含真实 SHA、审查问题、构建/测试证据、文件和增删行数。
- P3-07：Windows Electron 安装包携带所有相关 Skills/脚本，内网不需下载插件。
- P3-08：上游同步不侵入核心，插件关闭后 DSH 原生流程不受影响。

## 端到端用例

| 用例 | 条件 | 预期 |
|---|---|---|
| E2E-01 | 干净工作区 + 明确目标 | 自动完成并本地提交一次 |
| E2E-02 | 需求权限对象有歧义 | 具体问题确认前不实施 |
| E2E-03 | 走读发现 P1 问题 | 修复、重新走读、重新验证 |
| E2E-04 | 两轮重复相同问题 | 阻塞停止 |
| E2E-05 | 新建手动任务 | 不擅自调用下一阶段 |
| E2E-06 | S4 后切换模式 | 原任务和证据复用，无双重执行 |
| E2E-07 | S5 时终止桌面进程 | 恢复检查点，不自动续跑 |
| E2E-08 | S7 成功后修改源码 | 不允许直接提交 |
| E2E-09 | 启动前存在脏文件 | 不 reset、不覆盖、不纳入任务 |
| E2E-10 | 所有门禁通过 | 不发生 push / PR / remote commit |
| E2E-11 | Windows 断公网 | 现有本地模型与工具可用时能执行离线流程 |
| E2E-12 | SVN 仓库 | 自动停止在提交前，不能远程 svn commit |

## 安全原则

正确性 > 数据安全 > 最小改动 > 可验证性 > 速度 > Token。

**实现与验收必须分开记录**：文档中的 AC/E2E 只有在实际执行并保存环境、命令、退出码及证据后才可以标记为通过。单元测试通过不替代 Windows Electron/真实模型端到端验证。
