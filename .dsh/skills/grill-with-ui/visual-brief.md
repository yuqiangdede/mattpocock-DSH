# Grill Visual Brief

This is the required drawing specification for `grill-with-ui/SKILL.md`. Use it whether the visual is generated by a subagent or inline.

## Input and decisions
Read the session's `state.json` first. Questions, user answers, terms, durable decisions, constraints, deferred decisions, and visual feedback are the source of truth. Preserve every confirmed decision on redrawing; do not introduce features, workflows, buttons, entities, or data not supported by the discussion. If an existing application screenshot or design is provided, keep untouched areas and the product's existing navigation/styling.

## Output
Write a single UTF-8 `visual.html` file in the specified session directory.
- Prototype: show the real surrounding page and important click/hover/focus states; mock interactions must be local to the page.
- Diagram: show clearly labelled components and relationships with a logical hierarchy.
- Make the output readable on desktop and smaller widths, using legible text, accessible labels, and keyboard-operable controls.
- Use a neutral, clean, practical presentation; detailed functionality is more important than decorative effects.

## Isolation and security
The document is rendered in a sandboxed iframe. Keep HTML, CSS and JavaScript self-contained. No network calls, CDN, external scripts/fonts, analytics, secrets, arbitrary local-file access, or production API calls. Escape user-supplied text when generating markup; never insert it directly into an HTML string without proper encoding. Clearly identify example values and mocked states.

## Drawing lifecycle
Only the interviewing agent coordinates redraw, versions, and publishing. Draw from **all** current answers, not just the latest feedback. Do not race another in-flight draw or overwrite a newer visual. On completion return the file path plus a short description of what was changed; do not paste the full generated markup into the interview.
